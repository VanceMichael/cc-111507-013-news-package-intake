# 接收接口

服务通过本机来源网关取件；服务 URL 和来源 URL 不相同。`createService({dataDir, scenario})` 返回 baseUrl、gateway.baseUrl、store 及异步 close()，测试可直接启动，不依赖固定端口。所有用户可见错误采用中文。

- `GET /health`：进程健康。
- `GET /v1/source`：当前来源描述及 entry。
- `POST /v1/intakes`：JSON 对象，mode 为 raw 或 structured；其他字段按来源需要可含 filter、version、region、tables、view、query、client、basisPath。raw 只领取入口文件并记录元信息；structured 按 NewsML-G2 新闻包关系收件，语法错误返回400且不落收件，无法按包解释返回201的 rejected 收件，部分素材缺口返回201的 partial 收件。
- `GET /v1/receipts` 和 `GET /v1/receipts/{id}`：读取本地收件结果。

收件文件位于 DATA_DIR/receipts，原文位于 DATA_DIR/blobs，以 SHA-256 寻址。原始接收状态为 received；结构化收件结果的 state 使用 complete、partial、rejected，records 保存领域记录、issues 保存可定位问题、coverage 解释本次范围和完整性、evidence 保存来源字节、版本或关系依据。不能在仍有未知缺口时写 complete。正常收件返回201，语法错误400；来源部分失败可形成 partial 收件，完全无法解释可形成 rejected，不要求通过抛出异常丢掉原文。

结构化记录可增加领域字段，但来源定位必须可追溯，稳定身份不得仅使用数组下标。接收后查询返回相同记录；新的实例打开相同 DATA_DIR 仍可查询既有结果。请求只有本机合成来源，不接受任意互联网地址。

领域输出约定：records 按新闻包中的内容角色关系收件，role 保存已展开或原始限定名；每份素材可出现多个角色关系。

结构化收件字段约定（mode=structured）：

- records 按包内关系出现顺序排列，身份优先使用 residref，其次 href，不使用数组下标。每条记录含 itemVersion（itemRef 声明版本）、packageVersion（包版本，二者分别记录不互相替代）、available、blob 摘要、usages（组路径、组模式、组内位置、深度、备选组身份）与 roles（qcode、resolvedUri、解释 scope 与来源）。同一资源被多处引用时，每次角色关系独立保留。
- coverage 解释本次范围与完整性：package 保存包身份、pubStatus 与包级 catalog；versioning 并列包版本与每个内容项的声明/实测版本；groups 与 ordering 忠实保留 bag/sequence/alt 结构和排序；missingItems 列出未取得素材；editable 仅在无阻断缺口且包 pubStatus 为 usable 时为真，下载完成不等于可编辑；traversalScope 固定为 manifest-only；externalReferences 登记 remoteContent 等不自动遍历的链接；evidence 保存每份来源字节的 href、SHA-256、大小与来源 ETag。
- issues 使用稳定 code（resource-unavailable、not-downloaded、resource-outside-manifest、item-version-mismatch、group-cycle、dangling-group-ref、missing-href、item-not-usable、unsupported-extension、unsupported-item-type、unsupported-root 等），blocking 区分是否影响完整性；有阻断缺口时 state=partial，不能写 complete。
- 备选组（pgrmod:alt）中的每个 itemRef 保持独立关系：某一备选不可取得时只标记该关系缺口，不用另一备选稿替代原稿。
