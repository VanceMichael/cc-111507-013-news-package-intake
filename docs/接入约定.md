# 接收接口

服务通过本机来源网关取件；服务 URL 和来源 URL 不相同。`createService({dataDir, scenario})` 返回 baseUrl、gateway.baseUrl、store 及异步 close()，测试可直接启动，不依赖固定端口。所有用户可见错误采用中文。

- `GET /health`：进程健康。
- `GET /v1/source`：当前来源描述及 entry。
- `POST /v1/intakes`：JSON 对象，mode 为 raw 或 structured；其他字段按来源需要可含 filter、version、region、tables、view、query、client、basisPath。raw 只领取入口文件并记录元信息。structured 按 NewsML-G2 包内关系收件：解析 packageItem 的 groupSet/group/groupRef/itemRef，只领取来源清单内的 href，按内容角色关系生成 records。
- `GET /v1/receipts` 和 `GET /v1/receipts/{id}`：读取本地收件结果。

收件文件位于 DATA_DIR/receipts，原文位于 DATA_DIR/blobs，以 SHA-256 寻址。原始接收状态为 received；结构化收件结果的 state 使用 complete、partial、rejected，records 保存领域记录、issues 保存可定位问题、coverage 解释本次范围和完整性、evidence 保存来源字节、版本或关系依据。不能在仍有未知缺口时写 complete。正常收件返回201，语法错误400；来源部分失败可形成 partial 收件，完全无法解释可形成 rejected，不要求通过抛出异常丢掉原文。

结构化记录可增加领域字段，但来源定位必须可追溯，稳定身份不得仅使用数组下标。接收后查询返回相同记录；新的实例打开相同 DATA_DIR 仍可查询既有结果。请求只有本机合成来源，不接受任意互联网地址。

领域输出约定：records 按新闻包中的内容角色关系收件，role 保存已展开或原始限定名；每份素材可出现多个角色关系。record.package.version 是包的版本，record.version 是包要求的内容项版本，record.item.version 是实际收到的内容项版本，三者不互相替代。roleScheme 记录展开所用的目录作用域；目录别名只作用于所在文档。group.path、order 与 alternatives 保留组路径、声明顺序与备选组身份；pubStatus 在 coverage 中单独保存，usable/withheld/canceled 不合并。coverage.usable 为假时 unusableReasons 说明原因（撤回状态或素材缺口）；备选素材缺失时原关系保留缺口，不以其他备选稿顶替。
